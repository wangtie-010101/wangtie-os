# DDL 比较（SIT ↔ UAT 表结构差异）

「DDL 比较」菜单用于比较**两个环境**的表结构差异（建表信息、字段、主键、索引、注释、视图定义），
并把不同的内容逐条列出来，附左右两侧「由数据字典重建的 DDL」对照。

> 只做**只读比较**：不执行任何 DDL，也不会修改任何一个库。

## 连接信息放配置文件

页面**不需要填账号密码**，连接信息全部来自配置文件（页面只显示环境与文件路径，且**不会拿到密码**）。

配置文件查找顺序（**第一个存在的生效**）：

1. 环境变量 `DDL_ENV_CONFIG` 指定的路径；
2. `$DSH_HOME/wangtie-os/ddl-environments.json`（**从 3080 的 DSH 宿主访问时改这里最方便**）；
3. `<项目>/config/ddl-environments.local.json`（项目内覆盖，建议不要提交到 Git）；
4. `<项目>/config/ddl-environments.json`（**包内自带**默认值）。

文件格式（每套环境一段，`enabled: false` 可临时不参与比较）：

```json
{
  "environments": [
    {
      "key": "SIT", "name": "示例环境-sit",
      "host": "10.0.0.10", "port": 2883,
      "cluster": "OB_CLUSTER", "tenant": "obtenant_sit",
      "user": "OB_USER", "password": "<数据库密码>",
      "schema": "", "enabled": true
    },
    {
      "key": "UAT", "name": "示例环境-uat",
      "host": "10.0.0.10", "port": 2883,
      "cluster": "OB_CLUSTER", "tenant": "obtenant_uat",
      "user": "OB_USER_UAT", "password": "<数据库密码>",
      "schema": "", "enabled": true
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `key` / `name` | 环境标识（SIT / UAT）与显示名 |
| `host` / `port` | 地址与端口（ODP 2883 / 直连 observer 2881） |
| `cluster` / `tenant` | 集群名与租户名（一起拼成 `用户名@租户名#集群名`） |
| `user` / `password` | 数据库账号与密码 |
| `schema` | 要比较的模式（Oracle 里模式＝账号名）；**留空则取用户名** |
| `enabled` | `false` 时该环境不参与比较 |

**前两套**环境分别作为比较的**左侧**与**右侧**（顺序即配置里的顺序）。改完文件保存即可，页面重新比较就会用新配置（不需要重启服务）。

> ⚠️ 配置文件里是**明文密码**：注意文件权限，不要提交到代码仓库、不要外发。
> 若不想在仓库里放密码，可以只提交 `config/ddl-environments.json` 的模板，把真实密码写进被 Git 忽略的
> `config/ddl-environments.local.json`。

## 页面操作

1. 选择或直接打开「DDL 比较」菜单，页面顶部会显示**配置来源路径**与两套环境（地址、租户、账号、比较的模式、密码是否已配置）。
2. 可选填「对象名包含」缩小范围（例如只比 `BILL` 相关的表），选择是否「包含视图」「同时列出结构一致的对象」。
3. 点「🔍 开始比较」，结果分三块展示：
   - **概览**：只在左侧 / 只在右侧 / 结构不同 / 完全一致 的对象数量；
   - **差异明细**：每个对象一行，点开看该对象的差异清单与左右 DDL 对照；
   - 可「导出差异 CSV」，用于发给 DBA 或存档。

差异行的含义：

| 前缀 | 含义 |
| --- | --- |
| `+` | 右侧多出来的（字段 / 索引） |
| `-` | 右侧缺失的（字段 / 索引） |
| `~` | 两侧都有但不一样（类型、可空、默认值、注释、主键、索引列、视图定义…） |

## 比较内容与边界

- **表**：字段增删、字段类型、是否可空、默认值、字段注释、表注释、主键列、索引（名称/唯一性/列，主键自带索引不计）。
- **视图**：视图定义文本（`ALL_VIEWS.TEXT`）是否变化。
- **DDL 文本**是**由数据字典重建**的（`CREATE TABLE` / `CREATE OR REPLACE VIEW` / `COMMENT ON` / `CREATE INDEX`），
  用于对照阅读，不保证与原始建表语句逐字一致（不会还原分区、表空间、存储参数等物理属性）。
- 不做：数据比对、行数比对、存储过程/触发器/序列/同义词/权限等对象的比较。

## 比较失败怎么看（重要）

页面上的「🔌 测试两个环境」会**分别**连两套库，把结果标在各自的环境卡片上：

```
SIT · 示例环境-sit   ✓ 连接正常 · 128 个对象
UAT · 示例环境-uat   ✗ 连接失败
                      认证失败：账号、租户或密码不正确（账号需写成 用户名@租户名#集群名）（ER_ACCESS_DENIED_ERROR）
```

「开始比较」失败时同样会**指出是哪一侧失败、原因是什么**，例如：

```
比较失败：UAT（示例环境-uat）连接失败：认证失败：账号、租户或密码不正确…；
另一侧可正常读取：SIT 128 个对象；请检查配置文件里的 user / tenant / cluster / password：…/config/ddl-environments.json
```

常见原因（按出现频率）：

| 现象（服务端错误码） | 原因 | 处理 |
| --- | --- | --- |
| `ER_ACCESS_DENIED_ERROR` 认证失败 | 该环境的 `user` / `tenant` / `cluster` / `password` 与库不一致 | 对照「OceanBase 管理」里连得通的那套参数改配置文件；注意账号写法是「用户名」本身，租户与集群分开填 |
| `ORA-00942` 表或视图不存在 | `schema` 写错，或账号在该模式没有权限 | `schema` 留空＝取用户名；确认真实模式名 |
| `ORA-00904` 字段无效 | 该版本 Oracle 兼容字典缺列 | 一般已被自动降级处理；若仍报，把提示发出来 |
| `ETIMEDOUT` / `ECONNREFUSED` | 跑服务的那台机器连不到该地址/端口 | 用「OceanBase 管理」的同一台机器测一次 TCP 可达性 |

> 一句话：**「OceanBase 管理」里能连 ≠ DDL 比较能连** —— 后者用的是配置文件里那两套账号，逐套核对即可。

## 排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面提示「没有找到配置文件」 | 确认 `config/ddl-environments.json` 存在，或用 `DDL_ENV_CONFIG` 指定路径 |
| 提示「配置文件解析失败」 | JSON 格式问题（多逗号、引号未闭合），按提示里的路径修正 |
| 提示「至少要有两个环境」 | 配置里至少两套 `enabled: true` 的环境 |
| 比较很慢 / 超时 | 对象很多时先用「对象名包含」缩小范围；页面请求上限 120 秒 |
| 报 `ORA-xxxxx` 之类数据库错误 | 把提示原文发出来：常见是账号/租户写错、模式名不对（`schema` 留空时会取用户名） |
